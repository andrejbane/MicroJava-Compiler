# MicroJava Compiler

This project implements a compiler for an extended MicroJava language. It reads
a `.mj` source file, performs lexical, syntax, and semantic analysis, and emits
MicroJava bytecode in an `.obj` file that can be executed by the supplied
MicroJava runtime.

## How the compiler works

```text
MicroJava source (.mj)
        |
        v
JFlex lexer (Yylex)
        | tokens
        v
CUP parser (MJParser)
        | abstract syntax tree
        v
SemanticPass
        | typed AST + symbol table
        v
CodeGenerator
        | MicroJava bytecode
        v
Object file (.obj)
        |
        v
MicroJava runtime (rs.etf.pp1.mj.runtime.Run)
```

The complete compilation flow is:

1. **Lexical analysis** converts source characters into CUP tokens. Whitespace
   and `//` comments are ignored, while invalid characters and integer literals
   outside Java's `int` range are reported with their source location.
2. **Syntax analysis** applies the grammar from `spec\mjparser.cup` and builds
   the generated AST. Selected declaration, method-parameter, `if`, and
   assignment errors have recovery productions so parsing can continue and
   report a useful boundary.
3. **Semantic analysis** initializes the MicroJava symbol table, adds the
   `bool` type, opens and closes program/class/method scopes, resolves names,
   assigns types to AST nodes, and validates all declarations and expressions.
4. **Code generation** traverses the checked AST and emits instructions through
   `rs.etf.pp1.mj.runtime.Code`. It allocates global storage, method frames, and
   class virtual tables, resolves jumps and calls, and records `main` as the
   program entry point.
5. **Object writing** serializes the bytecode beside the source file using the
   same base name. Compiling `test\test301.mj`, for example, creates
   `test\test301.obj`.
6. **Execution** loads the `.obj` file into the supplied MicroJava virtual
   machine, which executes the generated bytecode and handles `read`/`print`.

Compilation stops before object-code generation if the lexer, parser, or
semantic pass reports an error. A stale object file with the target name is
removed before compilation starts.

## Implemented language features

### Types and declarations

- Built-in `int`, `char`, and `bool` types, plus the standard `chr`, `ord`, and
  `len` functions and the predefined `eol` constant.
- Global and local variables, constants, formal parameters, class fields, and
  one-dimensional arrays.
- Primitive constants, `null`-compatible reference types, object allocation,
  and array allocation.
- Required global `void main()` method without parameters.

### Expressions and statements

- Assignment, method calls, `++`, and `--`.
- Arithmetic operators `+`, `-`, `*`, `/`, and `%`, including unary minus.
- Relational operators `==`, `!=`, `>`, `>=`, `<`, and `<=`.
- Boolean conditions with `&&` and `||`.
- The conditional expression `condition ? first : second`.
- `if`/`else`, blocks, `for`, `foreach`, `break`, `continue`, and `return`.
- `read` and `print`, including an optional numeric print width.
- Array indexing and the `.length` property.

### Classes and dynamic dispatch

- Concrete and abstract classes.
- Single inheritance with `extends`.
- Fields, instance methods, the implicit `this` reference, and inherited
  members.
- Method overriding with signature validation.
- Abstract methods and checks that concrete subclasses implement all inherited
  abstract methods.
- Virtual method tables and runtime dispatch for overridden instance methods.
- Prevention of direct abstract-class instantiation.

### Array extensions

- `result = array.findAny(value);` checks whether a primitive value occurs in a
  one-dimensional array and stores a `bool`.
- `result = array.map(element => expression);` creates a transformed array.
- `foreach(element : array)` iterates over all array elements.

The semantic pass also checks duplicate declarations, undeclared names,
assignment compatibility, call argument counts and types, legal return values,
writable designators, loop-only `break`/`continue`, valid array indices, and
operator operand types.

## Requirements

Everything needed by the compiler itself is included in `lib\`. To build and
run it, install:

- A JDK with `java` and `javac`. The project targets **Java 8 bytecode** and can
  be built with JDK 8 or a newer JDK that supports `--release 8`.
- Eclipse IDE for Java Developers only if using the Eclipse workflow.
- Apache Ant only when regenerating the lexer/parser from `spec\` or using
  `build.xml`; it is not required for the direct `javac` workflow.

Check the command-line tools:

```powershell
java -version
javac -version
ant -version # only needed for the Ant workflow
```

Run all commands below from the project directory:

```powershell
Set-Location C:\dev\pp1domaci\workspace\MJCompiler
```

## Build and run from PowerShell

### 1. Compile the compiler and its drivers

The lexer, parser, and AST sources are already generated and committed, so a
normal build only needs `javac`:

```powershell
New-Item -ItemType Directory -Force bin | Out-Null
$sources = Get-ChildItem src,test -Recurse -Filter *.java |
    ForEach-Object { $_.FullName }
javac --release 8 -cp "lib/*" -d bin $sources
```

On JDK 8, replace `--release 8` with `-source 8 -target 8`.

### 2. Compile a MicroJava source file

`MJEverythingTest` is the end-to-end compiler driver. It accepts exactly one
`.mj` file:

```powershell
java -cp "bin;config;lib/*" `
    rs.ac.bg.etf.pp1.MJEverythingTest test\test301.mj
```

A successful run prints:

```text
Compilation succeeded: test\test301.mj
Object code written to: test\test301.obj
```

The `config` directory must be present on the classpath because it contains
`log4j.xml`.

### 3. Execute the generated object file

```powershell
java -cp "lib/mj-runtime.jar" `
    rs.etf.pp1.mj.runtime.Run test\test301.obj
```

`test301.mj` reads two integers from standard input. They can be supplied
interactively or piped into the runtime:

```powershell
"10 10" | java -cp "lib/mj-runtime.jar" `
    rs.etf.pp1.mj.runtime.Run test\test301.obj
```

### Compile another program

The output is always written beside the input:

```powershell
java -cp "bin;config;lib/*" `
    rs.ac.bg.etf.pp1.MJEverythingTest path\to\program.mj

java -cp "lib/mj-runtime.jar" `
    rs.etf.pp1.mj.runtime.Run path\to\program.obj
```

## Run from Eclipse

1. Start Eclipse and select `C:\dev\pp1domaci\workspace` as the workspace, or
   import `workspace\MJCompiler` with **File > Import > Existing Projects into
   Workspace**.
2. Configure an installed JDK under **Window > Preferences > Java > Installed
   JREs**. If Eclipse cannot resolve the existing `jdk-23` classpath entry,
   replace it with the installed JDK.
3. Build the project with **Project > Build Project**.
4. Run `test\rs\ac\bg\etf\pp1\MJEverythingTest.java` as a Java application.
5. In the run configuration, set the program argument to a source file such as
   `test\test301.mj` and set the working directory to the `MJCompiler` project.
6. Run `rs.etf.pp1.mj.runtime.Run` with `test\test301.obj` as its program
   argument to execute the generated bytecode.

The other driver classes can run individual phases:

| Main class | Behavior |
|---|---|
| `MJTest` | Tokenizes all bundled test sources. |
| `MJParserTest` | Parses the bundled sources and logs their ASTs. |
| `MJSemanticTest` | Parses and semantically checks the bundled sources. |
| `MJCodeGeneratorTest` | Runs the complete pipeline and writes `.obj` files. |
| `MJEverythingTest` | Compiles one requested source and prints a concise success or failure result. |

## Regenerate the lexer and parser

The generated Java sources should be rebuilt after changing either file in
`spec\`. With Apache Ant installed:

```powershell
ant compile
```

The default `compile` target performs these steps in order:

1. Deletes the previously generated parser, lexer, and AST sources while
   preserving the hand-written semantic and code-generation classes.
2. Runs CUP against `spec\mjparser.cup`.
3. Runs JFlex against `spec\mjlexer.flex`.
4. Compiles the generated and hand-written sources for Java 8.

The supplied JARs mean that no Maven or Gradle dependency download is needed.

## Tests and example programs

| Program | Purpose | Input |
|---|---|---|
| `test\test301.mj` | Arithmetic, arrays, `read`/`print`, ternary expressions, and `findAny`. | `10 10` |
| `test\test302.mj` | Parser error-recovery case plus methods, loops, conditions, and `map`. It intentionally contains the malformed expression `niz2[1 = 1` and must fail compilation. | Not executable |
| `test\test303.mj` | Abstract classes, inheritance, overriding, arrays of objects, virtual calls, and `for`. | `2` |
| `test\test304.mj` | The class hierarchy from test 303 exercised with `foreach`. | `2` |

Compile the valid examples:

```powershell
@("test\test301.mj", "test\test303.mj", "test\test304.mj") |
    ForEach-Object {
        java -cp "bin;config;lib/*" rs.ac.bg.etf.pp1.MJEverythingTest $_
        if ($LASTEXITCODE -ne 0) { throw "Compilation failed: $_" }
    }
```

`test302.mj` is useful for checking diagnostics. Its parser reports the syntax
error, recovers at the following semicolon, and the complete compiler correctly
refuses to produce `test302.obj`.

## Diagnostics and generated files

- Lexical errors are written directly to standard error with line and column
  information.
- Syntax and semantic diagnostics are written through Log4J.
- Warnings and errors appear on standard error.
- Detailed compiler logs are written to `logs\mj.log`.
- Generated object files are written next to their `.mj` source files.
- Generated lexer/parser/AST sources live under
  `src\rs\ac\bg\etf\pp1\` and `src\rs\ac\bg\etf\pp1\ast\`.

The implementation enforces the MicroJava VM limits used by the semantic pass:
at most 256 local variables per method and at most 65,536 global variables or
fields per class.

## Current scope

The compiler supports the language constructs listed above and emits code for
the bundled MicroJava virtual machine. `enum`, `switch`, and `case` are reserved
by the lexer but do not currently have parser productions or code-generation
support. Arrays are one-dimensional, and class inheritance is single
inheritance.
